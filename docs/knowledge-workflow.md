# 归档方法：事实、方法、代码、计划分开维护

编号：JKB-017 · 历史验证：部分验证 · 最近整理：2026-10-18

## 长台账为何难用
V8为1116行；历史基准与最新状态并存、重复命令和时间线与主题混排。读者难以判断当前入口、已验收与仅建议。
## 新组织
MD保存每次复盘；Notion每条一个主题，属性支持栏目/验证筛选；GitHub放代码、复现说明、实验记录和变更历史。
## 更新单元
一个session_id关联实验、证据、主题条目、脚本路径和commit；更新已有条目，避免每天新增同名教程。
## 发布规则
亲测结论标条件；重构版待复验；公共材料用环境变量/占位地址；不上传模型、视频、私有设备和账号凭据。
## 自动化边界
技能提供会话内默认流程；轮询只检查可读取的已保存材料，不声称能读取所有新聊天。

## 每次探索的固定流程

1. 建立 `YYYY-MM-DD-主题` 的 session_id，记录目标、环境、有效命令、关键输出和未解决项。使用 `python scripts/new_session.py 主题的英文短名` 创建模板。
2. 保存独立MD小结；原始台账只保留历史证据与新记录索引，不再无限追加完整教程。
3. 将稳定方法更新到对应主题文档。实验记录保留输入、预热、重复次数、精度、尺寸及测速范围；没有原始证据的内容标待验收。
4. 将可复用代码提取到 scripts/ 或 examples/，给出参数、依赖、输出、覆盖行为和验证状态。不要把对话里的半成品直接标为可用版本。
5. 更新Notion中的同编号主题、同路径脚本和同目标计划，附来源session_id及实际commit。
6. 同步CHANGELOG与ROADMAP；读回写入结果，只报告真正成功的目标。

## 跨会话衔接

仓库中的 AGENTS.md 提供贡献与归档约定；私人Notion记录实际目标位置和同步状态。定时检查只能处理已保存到可读取来源的新材料。它不会自动得到任意新聊天，也不会代替Jetson硬件验收。

同步以 session_id 和来源内容摘要去重。若仅改变同步标记，不产生新探索记录；失败的目标保留待重试状态。公开代码不得包含私人Notion地址、内部网络信息、账号凭据或设备序列号。
